# コワーキングスペース向けデジタル回数券アプリ MVP

紙で運用されているコワーキングスペース会員向けの回数券（1冊33枠、1枠100円相当、3,300円）をデジタル化し、スマートフォンでの残枠確認や利用消費をスムーズに行えるように開発された、Next.js (App Router) + Tailwind CSSベースのWebアプリケーション（MVPプロトタイプ）です。

Vercelなどのサーバーレス環境へのデプロイ時に404エラーが発生しないよう、すべてのプロジェクトファイルはリポジトリのルート（最上位階層）に配置されています。

---

## 📱 主要機能

### 1. 会員向け画面（マイページ）
- **ビジュアル残枠表示**: 保持している回数券の「残り枠数（例：残り 25/33 枠）」を美しい円形ゲージ（プログレスバー）で表示。
- **ワンタップ消費機能**: 1回あたり「1〜5枠」を選択し、スマホで押しやすい巨大なボタンで即座に消費可能。
- **誤操作防止アラート**: 「本当に消費しますか？」という消費後の残枠数が一目でわかる確認ダイアログ（モーダル）。
- **個人利用履歴**: いつ、何枠を消費したかを一覧でリアルタイム表示。

### 2. 店舗/管理者用機能（簡易版）
- **新規回数券の付与（販売登録）**: 管理者が会員のメールアドレスを指定し、33枠（3,300円分）またはお試し10枠の新規回数券を即座に付与・購入登録可能。
- **店舗全体の消費ログ**: 店舗全体での回数券消費履歴（誰が、いつ、何枠消費したか）をタイムラインで一元管理。
- **会員一覧と残枠状況**: 登録されている会員全員の現在の残枠状況を一覧で確認可能。

### 🧪 プロトタイプ検証用機能（デモ便利ツール）
- **検証用ロール切替（ヘッダー）**: ログイン画面を挟まずに、田中太郎（会員）、佐藤花子（会員）、管理者A（管理者）の間でワンタップで役割を切り替えてテスト可能。
- **デモ用アカウント新規登録**: 任意の名前とアドレスを入力するだけで、新しい会員や管理者を即座にその場で作成・ログイン可能。
- **DBリセット機能**: いつでもデータベースを初期のシード状態（田中太郎、佐藤花子のチケットあり）にリセットして、最初から検証をやり直すことができます。

## 🛠️ 技術スタック
- **フロントエンド / バックエンド**: Next.js 16 (App Router, Turbopack, TypeScript)
- **スタイリング**: Tailwind CSS v4 (スマホ向けに完全最適化したモバイルファースト設計)
- **データベース**: サーバレス/読み取り専用ファイルシステム環境（Vercelなど）に完全対応した、自動フォールバック機能付きファイルバックDB (`/tmp/database.json`)

## 🚀 ローカル環境での起動手順

### 1. 依存関係のインストール
プロジェクトのルートディレクトリで以下のコマンドを実行します。
```bash
npm install
```

### 2. 開発サーバーの起動
ローカルサーバーを起動します。
```bash
npm run dev
```
起動後、ブラウザで [http://localhost:3000](http://localhost:3000) にアクセスしてください。

### 3. プロダクションビルド & 起動 (検証用)
本番同様のビルドを行い動作を確認する場合：
```bash
npm run build
npm start
```

## 💾 データモデル設計

シミュレーションデータは `/tmp/database.json` に保存され、サーバーレス環境で書き込みが制限されている場合は、ステートフルなメモリ内ストアへシームレスに自動フォールバックします。

### 1. User (ユーザー)
```typescript
interface User {
  id: string;      // ユーザーID (例: 'usr-1')
  name: string;    // 名前 (例: '田中 太郎')
  email: string;   // メールアドレス (例: 'member1@example.com')
  role: 'member' | 'admin'; // ロール
}
```

### 2. Ticket (回数券)
```typescript
interface Ticket {
  id: string;               // チケットID (例: 'tkt-1')
  user_id: string;          // 所有者(ユーザー)ID
  total_slots: number;      // 初期枠数 (33)
  remaining_slots: number;  // 残り枠数
  status: 'active' | 'exhausted'; // 状態
  purchased_at: string;     // 購入日時 (ISO 8601)
}
```

### 3. UsageLog (利用履歴)
```typescript
interface UsageLog {
  id: string;          // ログID
  ticket_id: string;   // 回数券ID
  used_slots: number;  // 消費枠数
  used_at: string;     // 消費日時 (ISO 8601)
  user_name?: string;  // ユーザー名 (キャッシュ用)
  user_email?: string; // メールアドレス (キャッシュ用)
}
```

## 🧑‍💻 検証シナリオ例（おすすめの確認手順）

1. **初期状態の確認**:
   - 画面を開くとデフォルトで「田中太郎」としてログインしています。
   - 保有チケットが残り「25/33枠」であり、過去の2つの消費ログが「利用履歴」に並んでいることを確認します。
2. **回数券の消費**:
   - 消費枠数「2」を選択し、「2枠を消費する」の大きな紫のボタンを押します。
   - モーダルが立ち上がり、消費前の残り枠数（25枠）と消費後の予測残枠（23枠）が分かりやすく表示されます。
   - 「本当に消費する」をクリックし、ゲージが「23/33枠」にリアルタイムで減り、履歴に「2枠 消費」が追加されることを確認します。
3. **管理者画面での確認**:
   - ヘッダーの「検証用ロール切替」から `[管理者] 管理者 A` を選択します。
   - 「会員一覧・残枠状況」にて、田中太郎の残枠がリアルタイムで `残り 23 枠` になっていることを確認します。
   - 「店舗全体の消費履歴ログ」に、田中太郎がさきほど消費した `2枠 消費` のログが最上部に出ていることを確認します。
4. **新規回数券の付与**:
   - 管理者画面の「新規回数券の付与」フォームで、佐藤花子を選択するか、メールアドレス `member2@example.com` を入力します。
   - 「標準: 33枠」を選択した状態で「回数券を新規付与する」を押します。
   - 花子様の残枠状況が `残り 66 枠`（追加付与分）に増えることを確認します。
   - 「検証用ロール切替」で `[会員] 佐藤 花子` に切り替え、チケットがスタックされ、セレクトボックスで使用するチケットを切り替えられることを確認します。
